# Шаблон декомпозиции страницы "API-Контракты и Поток данных"

Если объект (дашборд, экранная форма, мнемосхема) содержит более 1 визуального компонента (графики трендов, таблицы), раздел "3. API-Контракты и Поток данных" **обязательно** декомпозируется на дочерние подстраницы покомпонентно.

## 1. Структура родительской страницы (Overview Hub)
- **Заголовок**: `3. API-Контракты и Поток данных (API-Contracts & Data Flow) [ObjectName]`
- **Содержимое**:
  - Краткое вводное описание.
  - Макрос `children` (для вывода оглавления вложенных компонентов).
  - Раздел `## Маппинг` со сводной таблицей привязки всех UI-показателей на уровне всей страницы (без порядкового номера в заголовке).
  - **Zero Duplication**: Запрещено дублировать персональные контракты компонентов на родительской странице.

## 2. Структура дочерних страниц (Компоненты)
Для каждой таблицы и графика создается собственная отдельная дочерняя страница.
- **Правило именования заголовков**: `3.<X>. <Тип компонента> «<Название>» [ObjectName]`  
  *(Пример: `3.1. График «Мощность агрегата» [CemisGtpp]`)*.

- **Внутренняя структура (текстовые разделы H2)**:
  Внутри каждой дочерней страницы создаются следующие разделы чистым текстом (не дочерними страницами!):

```html
<h2>API-Контракты</h2>
<p>Перечень используемых контроллеров и методов (например: GET /api/v1/data).</p>

<h2>Поток данных (Data Flow)</h2>
<p>Персональный «Запрос-Цепочка» согласно стандарту data_flow_chain_format.md.</p>

<h2>Маппинг</h2>
<p>Специфичный для данного компонента маппинг показателей (при необходимости).</p>
```
