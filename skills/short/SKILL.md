# Навык сжатия входного текста (Short / Text Compression)

Данный навык определяет инструкции по сжатию, суммаризации и редукции входных текстовых данных (технических спецификаций, журналов логов, трассировок, кода и описаний задач).

## 1. Алгоритм сжатия

### 1.0. Золотое правило (Максимальный приоритет)
- **Точность > Краткость**: Если сжатие (особенно ЕЯ) ведет к двусмысленности, потере граничных условий или критических деталей ТЗ → приоритет отдается точности и полноте. Сжимать только информационный шум, не затрагивая техническую суть.

### 1.1. Чат-ответы (лаконичность диалога)
- **Без шума**: исключать вежливость, приветствия, мета-рассуждения, вводные слова. Только сухие факты.
- **Синтаксис**: факты через инфинитивы. Использовать `→` (причина → следствие, элемент → действие).
- **Словарь сокращений**:
  - `DB`, `auth`, `config`, `env` (environment), `dep`/`deps` (dependency/dependencies).
  - `req` (request), `res` (response), `err` (error), `cb` (callback), `ctx` (context).
  - `fn` (function), `cmp` (component), `impl` (implementation), `plg` (plugin), `util` (utility).
  - `ref` (reference), `prop` (property), `var` (variable), `rec` (record), `init` (initialization).

### 1.2. Обработка контекста и файлов
- **Компактизация путей и ошибок**:
  - Формат: `путь/файл.ext:L15 → [суть проблемы]`.
  - В логах ошибок удалять строки из `node_modules`. Оставлять только саму ошибку и первую релевантную строку из `src/`.
- **Сжатие фрагментов кода (Code Stubbing)**:
  - Оставлять только измененные строки (до 10 строк в блоке), добавлять заголовок с относительным путем и строками: `// путь/файл.ext:L10-L15`.
  - Заменять неизмененный код, тела функций или неиспользуемые типы на `// ...` (сохраняя сигнатуры для контекста).
  - Избегать длинных diff-форматов с `+`/`-`, если это не требуется явно.
- **Сжатие структурированных данных**:
  - Сворачивать массивы/JSON до одного примера с комментарием `// xN элементов` (например, `[ { id: 1, ... } /* x100 */ ]`).

### 1.3. Сжатие естественного языка (ЕЯ)
- **Шаблон псевдокода**: формулировать мысли по схеме `[Объект/Контекст] → [Действие] (условия/детали)`.
- **Лимит длины**: до 7 слов на одну строку/пункт списка.
- **Активный залог**: использовать только активные глаголы или инфинитивы (`добавить`, `исправить`, `удалить` вместо `было добавлено`, `произведено удаление`).
- **Грамматическая редукция**: исключать местоимения (я, мы, этот, свой), союзы и связки без потери сути. Исключать дублирование контекста.
- **Аббревиатуры ЕЯ**: `т.к.` (потому что), `напр.` (например), `т.д.` (так далее), `ТЗ` (техническое задание), `док`/`доки` (документация), `фича` (функция).
- **Логические операторы**: заменять слова `и`, `или`, `не`, `если/то` на символы `&`, `|`, `!`, `?` / `→` (напр.: `err | !res`).
- **Минимизация разметки**: избегать заголовков 3-4 уровня в чате, использовать жирный текст `**Метка**:` и двоеточия.
- **Сжатие ссылок**: при повторном упоминании файлов/сущностей использовать индексы `[1]`, `[2]`.
- **Группировка по FSD/путям**: объединять файлы одной директории (напр. `shared: ui/btn, utils/math`).

## 2. Структура вывода
- **Построчно**: 1 факт = 1 строка.
- **Разделение**: список `- ` или пустая строка (`\n\n`), предотвращая слипание.
- **Сравнение вариантов**:
  ```text
  Var A: [описание] (+[плюс], -[минус])
  Var B: [описание] (+[плюс], -[минус])
  Rec: A → [короткая причина].
  ```

## 3. Примеры сжатия (Было → Стало)

### Текст / Требования (ЕЯ)
- **Было**: "Мы добавили валидацию полей в форму регистрации, чтобы пользователи не могли отправить пустые данные."
- **Стало**: "Форма registration → валидация полей (блок пустой отправки)."
- **Было**: "Если при получении профиля пользователя возникнет ошибка или профиль окажется пустым, то нужно выполнить сброс авторизации."
- **Стало**: `profile: err | !res → reset auth`

### Фрагмент кода
- **Было**:
  ```typescript
  export interface User {
    id: string;
    name: string;
    email: string;
    role: 'admin' | 'user';
  }
  export function processUser(user: User) {
    console.log("Processing user started...");
    if (user.role === 'admin') {
      doAdminStuff(user);
    } else {
      doUserStuff(user);
    }
    console.log("Processing user finished.");
  }
  ```
- **Стало**:
  ```typescript
  // src/utils/user.ts
  export interface User { id: string; role: 'admin' | 'user'; // ... }
  export function processUser(user: User) {
    // ...
    user.role === 'admin' ? doAdminStuff(user) : doUserStuff(user);
  }
  ```
