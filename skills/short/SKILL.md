# Навык сжатия входного текста (Short / Text Compression & ASD-STE100)

Данный навык определяет инструкции по сжатию, суммаризации и редукции входных текстовых данных (технических спецификаций, журналов логов, трассировок, кода и описаний задач) с использованием стандартов упрощенного технического языка ASD-STE100 (Simplified Technical English).

## 1. Алгоритм сжатия

### 1.0. Золотое правило (Максимальный приоритет)
- **Точность > Краткость**: Если сжатие (особенно ЕЯ) ведет к двусмысленности, потере граничных условий или критических деталей ТЗ → приоритет отдается точности и полноте. Сжимать только информационный шум, не затрагивая техническую суть.

### 1.1. Стандарты ASD-STE100 (Упрощенный технический язык)
- **Контролируемый словарь глаголов**:
  - Использовать строго фиксированный набор действий: `add` (добавить), `del` (удалить), `fix` (исправить баг), `move` (переместить), `update` (обновить), `split` (разделить), `merge` (объединить), `check` (проверить).
  - **ЗАПРЕЩЕНО**: Использовать размытые глаголы (`посмотреть`, `поправить`, `провести обработку`, `сделать`). 1 глагол = 1 однозначный смысл.
- **Ограничение цепочек существительных (Noun Stacks)**:
  - Максимум 3 существительных подряд. Вместо `user auth token refresh error logic` → `auth token refresh error`.
- **Лимит длины и структура мыслей**:
  - Максимум 15-20 слов на 1 мысль/строку. 1 мысль = 1 строка.
- **Императив / Активный залог (Imperative / Active Voice)**:
  - Использовать только инфинитивы или повелительное наклонение (`удалить X`, `обновить Y`).
  - **ЗАПРЕЩЕНО**: Использовать пассивный залог (`было добавлено`, `произведено удаление`).
- **Запрет неопределенных указателей**:
  - Исключать указательные местоимения (`это`, `данный`, `тот`, `свой`). Заменять на явное имя файла, компонента или относительный путь.
- **Однозначные логические союзы**:
  - Запрет неясных союзов (`как`, `при этом`, `в то время как`).
  - Строгая замена на символы: `?` (если), `→` (то/следствие), `!` (не), `&` (и), `|` (или).

### 1.2. Чат-ответы (лаконичность диалога)
- **Без шума**: исключать вежливость, приветствия, мета-рассуждения, вводные слова. Только сухие факты.
- **Синтаксис**: факты через инфинитивы. Использовать `→` (причина → следствие, элемент → действие).
- **Словарь сокращений**:
  - `DB`, `auth`, `config`, `env` (environment), `dep`/`deps` (dependency/dependencies).
  - `req` (request), `res` (response), `err` (error), `cb` (callback), `ctx` (context).
  - `fn` (function), `cmp` (component), `impl` (implementation), `plg` (plugin), `util` (utility).
  - `ref` (reference), `prop` (property), `var` (variable), `rec` (record), `init` (initialization).

### 1.3. Обработка контекста и файлов
- **Компактизация путей и ошибок**:
  - Формат: `путь/файл.ext:L15 → [суть проблемы]`.
  - В логах ошибок удалять строки из `node_modules`. Оставлять только саму ошибку и первую релевантную строку из `src/`.
- **Сжатие фрагментов кода (Code Stubbing)**:
  - Оставлять только измененные строки (до 10 строк в блоке), добавлять заголовок с относительным путем и строками: `// путь/файл.ext:L10-L15`.
  - Заменять неизмененный код, тела функций или неиспользуемые типы на `// ...` (сохраняя сигнатуры для контекста).
  - Избегать длинных diff-форматов с `+`/`-`, если это не требуется явно.
- **Сжатие структурированных данных**:
  - Сворачивать массивы/JSON до одного примера с комментарием `// xN элементов` (например, `[ { id: 1, ... } /* x100 */ ]`).

### 1.4. Сжатие естественного языка (ЕЯ)
- **Шаблон псевдокода**: формулировать мысли по схеме `[Объект/Контекст] → [Действие] (условия/детали)`.
- **Грамматическая редукция**: исключать местоимения, лишние предлоги и дублирование контекста.
- **Аббревиатуры ЕЯ**: `т.к.` (потому что), `напр.` (например), `т.д.` (так далее), `ТЗ` (техническое задание), `док`/`доки` (документация), `фича` (функция).
- **Минимизация разметки**: избегать заголовков 3-4 уровня в чате, использовать жирный текст `**Метка**:` и двоеточия.
- **Сжатие ссылок**: при повторном упоминании файлов/сущностей использовать индексы `[1]`, `[2]`.
- **Группировка по FSD/путям**: объединять файлы одной директории (напр. `shared: ui/btn, utils/math`).

## 2. Структура вывода
- **Построчно**: 1 факт = 1 строка.
- **Разделение**: список `- ` или пустая строка (`\n\n`), предотвращая слипание.
- **Сравнение вариантов**:
  ```text
  Var A: [описание] (+[плюс], -[минус])
  Var B: [описание] (+[плюс], -[минус])
  Rec: A → [короткая причина].
  ```

## 3. Примеры сжатия (Было → Стало)

### Текст / Требования (ЕЯ + ASD-STE100)
- **Было**: "Мы добавили валидацию полей в форму регистрации, чтобы пользователи не могли отправить пустые данные."
- **Стало**: "Форма registration → add валидация полей (блок пустой отправки)."
- **Было**: "Если при получении профиля пользователя возникнет ошибка или профиль окажется пустым, то нужно выполнить сброс авторизации."
- **Стало**: `profile: err | !res → reset auth`
- **Было**: "Нами была произведена оптимизация модуля обработки запросов аутентификации пользователей."
- **Стало**: `auth: req handler → refactor & optimize`

### Лог ошибки сборки
- **Было**:
  ```text
  TypeError: Cannot read properties of undefined (reading 'map')
      at renderList (src/components/List.tsx:15:23)
      at Object.fn (node_modules/react-dom/cjs/react-dom.development.js:10523:12)
      at runEffects (node_modules/react-dom/cjs/react-dom.development.js:12003:9)
  ```
- **Стало**:
  `src/components/List.tsx:L15 → TypeError: Cannot read properties of undefined (reading 'map')`

### Фрагмент кода
- **Было**:
  ```typescript
  export interface User {
    id: string;
    name: string;
    email: string;
    role: 'admin' | 'user';
  }
  export function processUser(user: User) {
    console.log("Processing user started...");
    if (user.role === 'admin') {
      doAdminStuff(user);
    } else {
      doUserStuff(user);
    }
    console.log("Processing user finished.");
  }
  ```
- **Стало**:
  ```typescript
  // src/utils/user.ts
  export interface User { id: string; role: 'admin' | 'user'; // ... }
  export function processUser(user: User) {
    // ...
    user.role === 'admin' ? doAdminStuff(user) : doUserStuff(user);
  }
  ```
