# Декомпозиция и Шаблон TASK-файла

## 📌 Правила

- **Путь/имя**: корень проекта `./TASK-[kebab-name].md` (или `-01.md`, `-02.md`).
- **Размер**: 100–150 строк на файл max.
- **Связи**: указание `Зависимости` и `Следующий шаг`.
- **Zero Dead Code**: обязательный пункт очистки устаревшего кода в каждом чек-листе.

---

## 📝 Шаблон `TASK-[kebab-name].md`

````markdown
# TASK: [Название]

## 🎯 Цель и Контекст
[Описание, FSD-слои, правила]
- **Зависимости**: Нет / `TASK-[kebab-name]-01.md`
- **Следующий шаг**: `TASK-[kebab-name]-02.md` / Финал

## 📐 Архитектура и Контракты
- **Файлы**: `path/to/file.ts`
- **[DELETE] Устаревшие файлы**: `path/to/unused.ts` (при рефакторинге/Zero Dead Code)
- **Типы/Интерфейсы**:
```typescript
// TS-контракты
```

## 📋 Чек-лист
- [ ] 1. Типы и утилиты
- [ ] 2. Бизнес-логика / стор
- [ ] 3. UI и интеграция
- [ ] 4. Создать/обновить локальный TROUBLESHOOTING.md (при багфиксе в плагине/модуле)
- [ ] 5. Очистка кода (Zero Dead Code): удаление устаревших импортов, неиспользуемых типов и закомментированных блоков

## 🛠 Валидация
- **Валидация**: `npx tsc --noEmit` (особенно на стыках cmp/plg) | `npm run lint` | Ручной тест
````
