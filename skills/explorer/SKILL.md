# Режим Explorer (Проектирование и Исследование)

Совместное проектирование изменений в проекте (фичи, рефакторинг, архитектура, стейт, UI).

---

## 🔑 Ключевые Принципы

> [!IMPORTANT]
> **Ограничение сканирования**:
> - Запрет сканирования всей базы (`list_dir`, `grep_search`) до уточнения задачи.
> - Разрешено: правила (`.agents/AGENTS.md`, `rules/`), явные файлы, MCP Read-Only (`get_editor_state`, `inspect_item`).
> - Непонятности → вопросы в чат / `ask_question`.

> [!IMPORTANT]
> **Обязательное согласие пользователя (Approval)**:
> - Запрещено создавать планы, ТЗ, TASK-файлы или переходить к следующему этапу проектирования без получения явного согласия пользователя в чате.
> - Каждый переход между этапами требует подтверждения. Агент обязан остановиться и спросить разрешение на продолжение.

> [!TIP]
> **Проектирование без рабочего кода**:
> Разрешены только TS-типы, интерфейсы, схемы, псевдокод. Кодинг строго на этапе выполнения (`/resolve`).

## 📋 Порядок Выполнения

1. **Сбор требований**: оценка запроса & контекста (активно использовать MCP: `get_editor_state`, `get_items_tree` и др.) → вопросы → согласование проверок. При мелких фиксах → Fast Track (пропуск 3 вариантов). **[Остановка: согласие на переход к вариантам / Fast Track]**
2. **3 Варианта**: формирование подходов (Быстрый, Рекомендуемый, Масштабируемый) в сжатом виде по правилам `.agents/skills/short/SKILL.md` → [options_structure.md](references/options_structure.md). **[Остановка: опрос/согласие на выбор варианта]**
3. **Составление ТЗ**: цель → приемка → FSD-план → проверка. **[Остановка: согласие на создание TASK-файлов]**
4. **TASK-файлы**: декомпозиция в `./TASK-[kebab-name].md` (100–150 строк, Zero Dead Code, блок `[DELETE]`, `TROUBLESHOOTING.md` при багах plg) → [task_template.md](references/task_template.md). **[Остановка: согласие на финализацию/запуск]**
5. **Финализация**: выбор сценария handoff (TASK-файлы, Pure Q&A, Прямой `/resolve` / Fast Track) → [handoff_scenarios.md](references/handoff_scenarios.md).
