# Архитектурный аудит (Architectural Audit Rules)

Правила соответствия требованиям `.agents`. Нарушение → стоп → авто-запуск `debug` (см. Шаг 3 в `SKILL.md`).

---

### 1. Язык
- Комментарии, JSDoc, коммиты → строго на русском.

### 2. Разделение экспортов (Fast Refresh)
- React-компоненты экспортируют только сам компонент. Хелперы/UI-конфиги → локально в `components.tsx`, `utils.ts`.

### 3. Сцепленность и связанность (Coupling & Cohesion)
- **Импорты между плагинами** → запрещены напрямую. Общий код → в `shared` или ядро подсистемы.
- **Импорты суб-плагинов** → запрещены напрямую. Связь через стор, события или API.
- **Контракты** → строгое соответствие TS-интерфейсам в `guide.md`/`types.ts`. Запрет костыльного расширения.
- **Поиск по имени** → запрещен `plugins.find(p => p.name === '...')`. Опрос через Capability/Adapter в `model/types.ts` и циклы.
- **Адаптеры возможностей** → запрещен `any` или `Record<string, any>` для API возможностей; использовать строго типизированные интерфейсы из `model/types.ts`.
- **Типы чужих доменов** → запрещено проверять чужой `item.type` (например, `item.type === 'foreign-type'`). Опрашивать Capability соседа.
- **Свойства чужого объекта** → запрещен прямой доступ к специфичным полям (например, `foreignSpecificField`). Доступ через context/API плагина-владельца.
- **Push-регистрация** → запрещена `registerAdapter` в onMount. Реализовать Pull-опрос (метод типа `getCapabilityAdapter`).
- **Обход реестра** → запрещен опрос fallback-хуков в обход единой точки реестра подсистемы.
- **Устаревшие вызовы** → запрещено сохранять обертки с приоритетом над новой системой. Сначала новая система, затем fallback.
- **Транзитные свойства** → запрещено писать в `mutatedItem` новые свойства вне целевых каналов. Изменения только через `capabilityAdapter.applyTransform`.
- **Вычисления в UI/оверлеях** → запрещен прямой импорт вычислительных утилит в UI-компоненты/оверлеи. Расчеты делать в Zustand-сторе родителя, оверлеи только рендерят.

### 4. FSD
- Импорты сверху вниз (`app` -> `pages` -> `widgets` -> `features` -> `entities` -> `shared`). Глубокие импорты и кросс-импорты слайсов запрещены. Публичный API → строго через `index.ts`.

### 5. Стандарты кодирования
- TS → строгий, без `any` и `as any`. Безопасный каст: `(item as { customProp?: boolean })`.
- Код-детекторы → запрещены `@ignore`, `// @ts-expect-error` без причин. Zustand-стор → строго селекторы. Именование: PascalCase (компоненты/типы), camelCase (переменные/хуки), kebab-case (файлы/папки).
- Заглушки → запрещены `TODO`, `FIXME`, `console.log`, временный UI.
- Стили → запрещен `style={{...}}` (кроме динамических координат/размеров). Использовать Tailwind v4 и `@shared/ui`.
- Useless assignment → запрещена инициализация переменных перед `if/else`, если они перезаписываются во всех ветках (объявлять `let x: type;`).
- Каст window/document → приводить к Record-типам через `unknown` (например, `window as unknown as Record<...>`).
- Типизация Promise/Worker → указывать точные возвращаемые типы вместо общего `unknown`.
- Хоткеи и фокус → использовать `code` (например, `KeyS`) вместо `key`; проверять фокус ввода: `if (e.target instanceof HTMLInputElement || e.target instanceof HTMLTextAreaElement) return;`.

### 6. Лимиты строк
- Обычные файлы / локальные `utils.ts`/`components.tsx` → лимит 300 строк (не относится к тестам).
- Оркестраторы плагинов (`index.tsx`) → лимит 800 строк.
- Файл 300–500 строк → предупреждение `[!]`. >500 строк (или оркестратор >800) → нарушение `[✗]` → рефакторинг.
- Воркеры → использовать суффикс `-worker.ts` вместо `.worker.ts` (eslint kebab-case).
- Общий код плагинов → запрещено создавать/предлагать общие хелперы между плагинами во внешних файлах. Только локальная реализация.

### 7. Тесты
- Запрещено удалять/отключать assertions в существующих тестах. Сбой теста → чинить код.

### 8. Zero Dead Code
- Неиспользуемые импорты, локальные переменные → удалить.
- Unused variables → полностью удалять неиспользуемые параметры функций и коллбэков (префикс `_` не отключает eslint `no-unused-vars`).
- Неиспользуемые экспорты → если только локально → убрать `export`, если не используется вообще → удалить.
- Мертвые файлы (не импортируемые) → удалить.
- Старая реализация при рефакторинге → удалить полностью.

### 9. История изменений (Undo/Redo & State Commit)
- Фиксация событий изменений (`state-commit`) → строго в конце интерактивной операции (`onMouseUp` / `onPointerUp`), не на каждый шаг перемещения.

### 10. Документация (guide.md)
- Плагины/модули должны содержать `guide.md` на английском языке, полностью отражающий код без расхождений.

### 12. Защита забандленных модулей
- Запрещено читать/изменять `index.js` забандленных плагинов/модулей.
- Поиск пуст, но есть `index.js` → стоп поиск → не сканировать git → уведомить о закрытом бандле → запрос подтверждения у юзера.

### 13. Оптимизация React 19
- Запрещен setState в useEffect при смене пропсов (делать в рендер-фазе).
- Запрещено читать `ref.current` в рендере (JSX). Размеры читать в useLayoutEffect / ResizeObserver и писать в стейт.

### 14. TS7022
- В циклических обходах указывать типы промежуточных переменных для разрыва кольцевой зависимости вывода типов.

### 15. Shared UI
- Кнопки, инпуты, модалки → импорт строго из `@shared/ui`. Запрещено верстать дублирующие UI-элементы со своими стилями.

### 16. Иерархия parentId
- `parentId` полиморфен (элемент в контейнере, группа в слое и т.д.). `!item.parentId` → нет родителя вовсе.
- Корневой элемент в иерархии → проверять контекстный тип родителя. Создавать специализированные утилиты `isRootEntity(node, pool)` (избегать наивных проверок одного поля).

### 17. Кэширование и синхронизация
- Сброс кэша → при макросах, пакетных загрузках, импорте сбрасывать локальные кэши (`domainStore.getState().clearCache()`).
- Синхронизация → изменение базовой структуры элементов должно атомарно обновлять зависимые производные данные.
- Ключ кэша (`cacheKey`) → включать все управляющие параметры алгоритма и связи сущностей.
