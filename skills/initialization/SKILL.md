# Навык Initialization (Инициализация правил проекта)

Интерактивное проектирование и заполнение файлов правил в `.agents/rules/` (`context.md`, `project-rules.md`, `architecture.md`) под конкретный проект.

---

## 🔑 Ключевые Принципы

> [!IMPORTANT]
> **Предварительный вывод структуры вопросов**:
> До начала интервью СТРОГО ОБЯЗАТЕЛЬНО вывести пользователю полную структуру предстоящих вопросов и блоков.

> [!IMPORTANT]
> **Интерактивный режим с готовыми вариантами ответов**:
> Для каждого вопроса агент обязан предложить минимум 3 варианта:
> 1. `[Авто-определение]` — вариант на основе сканирования кодовой базы/`package.json`.
> 2. `[Рекомендуемый стандарт]` — проверенное решение для данного типа стека.
> 3. `[Альтернатива / Свой вариант]` — гибкий выбор пользователя.

---

## 📋 Порядок Выполнения

### Этап 1: Предварительный анализ и Анонс структуры
1. Сканировать файлы проекта (`package.json`, `tsconfig.json`, структуру `src/`).
2. Вывести дерево вопросов:

```markdown
📋 **План интерактивной инициализации правил проекта**:

1. **Контекст проекта (`context.md`)**:
   - Назначение/суть приложения
   - Технологический стек

2. **Технические стандарты (`project-rules.md`)**:
   - Правила shared-модулей
   - Стандарты React/TypeScript/Стейта
   - Стилизация и UI-контраст
   - Тестирование

3. **Архитектура и Контракты (`architecture.md`)**:
   - Слои архитектуры (`core`, `ui`, `state`, `shared` и др.)
   - Изоляция слоев и контракты модулей
```

3. Запросить подтверждение перехода к диалогу.

---

### Этап 2: Диалог с готовыми вариантами (Q&A)
По каждому блоку агент формирует вопрос с 3 готовыми опциями (используя `ask_question` при наличии выбора):

- **Пример**:
  - *Вопрос*: «Какой паттерн архитектуры используем для разделения слоев?»
  - *Вариант 1 (Авто)*: Modular Layered Architecture (`src/core`, `src/ui`, `src/state`).
  - *Вариант 2 (Рекомендуемый)*: Feature-Sliced Design (FSD).
  - *Вариант 3 (Простой)*: Flat/Component-Based Architecture (`src/components`, `src/hooks`).

---

### Этап 3: Запись файлов по шаблонам
После согласования всех ответов подставить значения в референсные шаблоны:
- `references/context_template.md` → `.agents/rules/context.md`
- `references/project_rules_template.md` → `.agents/rules/project-rules.md`
- `references/architecture_template.md` → `.agents/rules/architecture.md`
